    What this is

    A focus timer bound to one task. Focus → break → next sprint, repeating until the focused minutes add up to the goal. Defaults: 25 min focus, 5 min break, a 60 min goal.

    Decisions baked into the mockup

    • Breaks start on their own; the next focus sprint waits for a click, so nobody is pulled back in mid-rest.
    • Only focused minutes count toward the hour. Breaks never count.
    • When less than a full sprint is left, the next sprint is shortened to close the hour exactly: 25 + 25 + 10.
    • The demo opens at 50 of 60 minutes so you can see that closing sprint. Reset demo starts from zero.
    • One active sprint at a time. Starting on another task switches the sprint and credits the elapsed minutes to the old task.
    • Timer controls are labelled steppers, so the current value is always visible. A focus change mid-sprint takes effect on the next sprint.
    • The menu-bar pill keeps the timer visible while you are in Notes or the calendar.
    • Superseded: the always-visible play button on every task row is too much timer chrome. See mockups/focus-iterations.html for four quieter activation directions.

    New task / New event

    • Today shows New task; Calendar shows New event with the selected date pinned in the quick bar.
    • Both open the same capture bar, so the label changes but the muscle memory does not.
    • Decided: an event is a real calendar item with a start time and duration. It is not a task with a date, so it has no checkbox, no Done state, and no focus sprint.
    • The time and duration chips are clickable; the full form exposes both fields. Exported calendar files use timed start and end values for events.

    Open questions

    • Long break after four sprints, or keep every break at five minutes?
    • Write each finished sprint to the Logbook, or keep focus history on the task only?
    • At the end of a sprint: browser notification, chime, or both?
